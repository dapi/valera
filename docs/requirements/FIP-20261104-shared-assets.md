# FIP: непрерывная доставка ассетов

**Статус:** In Progress
**Создан:** 04.11.2026
**Приоритет:** High

## Проблема и решение
При rolling update новый HTML и запрос CSS могут попасть на разные версии web. Доставка писем отдельно проверена по двум собственным входящим; почтовый транспорт менять не требуется.

Ассеты всех выпусков публикуются в append-only PVC на существующем `raid-office2-retain`. Каждая реплика сохраняет свой локальный Propshaft manifest, но общий middleware обслуживает fingerprint-файлы всех версий. Init-публикация проходит до готовности новой реплики. Подменять существующий файл с тем же именем запрещено; полные SHA256 проверяются перед записью. Каталог доступен web только на чтение. Manifest и другие mutable/приватные файлы не выдаются.

## Безопасный переход
1. Bootstrap-init из существующего immutable image 0.44.2 копирует только public/assets в временный volume.
2. Publisher нового image сохраняет старые и новые файлы на PVC и отдельный immutable bootstrap manifest вне публичного каталога.
3. Первый rollout использует bootstrap manifest: HTML обеих версий запрашивает прежние ассеты.
4. После полного перехода всех web-реплик на shared middleware убрать bootstrap override и seed-init. Последующие rollout автоматически публикуют новые ассеты в тот же каталог до ready.

PVC создаётся отдельным Helm release с wait=false (WaitForFirstConsumer), основной release зависит от него. Приложение остаётся на office2. Ресурсы существующих контейнеров не уменьшаются. Shared данные автоматически не удаляются; storageClass Retain и keep annotation.

## Приёмка
Проверить GET/HEAD/Range, запрет traversal/manifest, идемпотентную повторную публикацию, отказ при коллизии. Во время перекрытия двух ReplicaSet запрос неизвестного старой локальной сборке fingerprint должен вернуть одинаковые bytes/200 через обе реплики. Проверить страницы и Telegram/GoodJob после выпуска.
